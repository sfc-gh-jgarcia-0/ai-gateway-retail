### 13. Patch `sql/setup.sql` — missing grants and placeholder host

The original `setup.sql` has two issues that cause failures on a fresh deploy:

**A. Missing schema-level grants for SYSADMIN**

The script creates all tables and the warehouse as ACCOUNTADMIN (sections 1–4), then switches to SYSADMIN at line 1290 for the remaining objects (EVAL_PROMPTS view, OPTIMIZATION_RUNS/RESULTS tables). But it never grants SYSADMIN the required CREATE privileges on the schema. Add these grants in the ACCOUNTADMIN block (after the existing grants around line 1286, before `USE ROLE SYSADMIN`):

```sql
-- Add after the existing GRANT APPLY TAG ON ACCOUNT TO ROLE SYSADMIN; line
GRANT ALL PRIVILEGES ON DATABASE CORTEX_GATEWAY_RETAIL_LAB TO ROLE SYSADMIN;
GRANT ALL PRIVILEGES ON SCHEMA CORTEX_GATEWAY_RETAIL_LAB.PUBLIC TO ROLE SYSADMIN;
```

Without this, `CREATE VIEW EVAL_PROMPTS` and `CREATE TABLE OPTIMIZATION_RUNS/RESULTS` both fail with `Insufficient privileges to operate on schema 'PUBLIC'`.

**B. Placeholder `<org>-<account>` in the network rule**

The `GATEWAY_APP_EGRESS` network rule contains a literal `<org>-<account>.snowflakecomputing.com` placeholder that fails with `unresolvable host name`. Replace it with the actual account host. To find the correct value:

```sql
SELECT CURRENT_ORGANIZATION_NAME() || '-' || CURRENT_ACCOUNT_NAME() || '.snowflakecomputing.com';
```

Then substitute the result into the `VALUE_LIST`. For example, for account `sfsenorthamerica` / `jgarcia_demo_uswest2`:

```sql
VALUE_LIST = ('pypi.org', 'pypi.python.org', 'pythonhosted.org', 'files.pythonhosted.org',
              'sfsenorthamerica-jgarcia_demo_uswest2.snowflakecomputing.com');
```

Alternatively, add a comment block above the statement reminding the user to replace the placeholder before running.
